How playlists work — URLs, folder import & FRITZ!NAS
"Alexa, öffne meine plattenkiste und spiele <Playlist>" plays these URLs in order. Repeat starts over after the last track, Announce has Alexa say "Ich spiele …" first, Shuffle randomises the order, Resume picks up where the playlist last stopped — as a whole track again (albums) or to the second (audiobooks).
Every URL must be https:// and deliver the file directly, without a preview page or login: Dropbox needs ?dl=1, Nextcloud share links need /download, Google Drive usually does not work. Check URLs fetches each link the way the Echo does and reports status, content type and range support (without ranges, "weiter" restarts the track).
A whole folder at once: paste a folder share link into Import folder — a FRITZ!NAS share (…/nas/filelink.lua?id=…), a Nextcloud folder or a plain directory index — and every audio file behind it is added below as its own track. Nothing is stored until you press Save Playlist.
FRITZ!NAS folder shares take a detour, and they have to: such a share hands out its files only with a session number, and the box ties that number to the address that fetched it — for the Echo it is worthless, whoever fetched it. The tracks therefore point at this app, which fetches the file itself and passes the bytes through. Nothing is stored; the counter below the list says how much ran through this month.
